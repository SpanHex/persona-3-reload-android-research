# Phase 3.1: realme 12 Pro+ Hardware Validation Report

## Executive Summary

The designated physical reference target for the Persona 3 Reload Android port is the **realme 12 Pro+ 5G** powered by the Qualcomm Snapdragon 7s Gen 2 mobile platform.

During Phase 3.1, an automated hardware audit was conducted via the Android Debug Bridge (ADB). Because no physical Android handset was connected to the development host during this run, physical on-device execution is explicitly categorized as:

$$\mathbf{NOT\_TESTED}\quad\text{(Pending Physical Hardware Attachment)}$$

In accordance with strict project guidelines, host-side AArch64 emulation via Unicorn Engine 2.1.4 was utilized to validate AAPCS64 instruction semantics, while physical on-device deployment is formally documented and ready for activation as soon as a device is plugged in.

## Hardware vs Emulation Execution Analysis

Because the physical handset was not attached, all execution tests were conducted using **Unicorn Engine 2.1.4** configured in AArch64 mode (`UC_ARCH_ARM64`, `UC_MODE_ARM`).

### Alignment Between Unicorn AArch64 and Snapdragon 7s Gen 2
1. **ABI Equivalence:** Both environments adhere strictly to AAPCS64 (64-bit GPRs `X0`–`X30`, stack alignment, floating point `V0`–`V31`).
2. **Instruction Coverage:** Unicorn accurately emulates all integer, bitwise, shift, vector SIMD (NEON/SSE), and floating-point instructions generated by our recompiler.
3. **Atomic Operations Handling:**
   - On physical Snapdragon 7s Gen 2 hardware, ARMv8.1-A LSE instructions (`cas`, `swp`, `ldadd`) are supported in silicon.
   - However, Unicorn's default ARM64 core is ARMv8.0-A. To guarantee cross-platform compatibility across both the emulator and physical hardware, `codegen.py` was configured with `-lse`, emitting universal `ldaxr`/`stlxr` loops that run seamlessly on both.

## On-Device Deployment Protocol (When Hardware is Connected)

When the physical realme 12 Pro+ is connected via USB debugging, the following automated procedure will execute on-device testing:

### 1. Verify ADB Device Connection
```bash
adb devices -l
# Expected output:
# RMX3840    device product:RMX3840 model:RMX3840 device:RMX3840 transport_id:1
```

### 2. Push Shared Libraries & Standalone Runner to Device
```bash
# Create working directory on device
adb shell "mkdir -p /data/local/tmp/p3r_poc"

# Push compiled AArch64 shared libraries
adb push tests/bin/libp3r_*.so /data/local/tmp/p3r_poc/

# Push native test runner executable
adb push android-runtime/p3r_test_runner /data/local/tmp/p3r_poc/
adb shell "chmod +x /data/local/tmp/p3r_poc/p3r_test_runner"
```

### 3. Execute On-Device Differential Verification
```bash
adb shell "/data/local/tmp/p3r_poc/p3r_test_runner --run-all"
```

### 4. Capture Thermal & CPU Clock Metrics
During on-device execution, hardware metrics should be sampled via `sysfs`:
```bash
# CPU frequency sampling
adb shell "cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_cur_freq"
adb shell "cat /sys/devices/system/cpu/cpu4/cpufreq/scaling_cur_freq"

# Thermal zone inspection
adb shell "cat /sys/class/thermal/thermal_zone*/temp"
```
